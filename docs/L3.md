## 3. Reflection

### 1. Sad path ของคู่จับความต้องการข้อใดที่บัตรไม่ได้พูดถึง และลูกค้าจะเห็นด้วยหรือไม่
บัตร Story ใบที่ 2 (`Sort movies`) ระบุเพียงการเรียงลำดับรายการหนัง แต่ไม่ได้พูดถึงกรณีที่แค็ตตาล็อกไม่มีหนังอยู่เลย (empty catalog) เราจึงเพิ่ม Sad path `Given the catalog is empty` เพื่อยืนยันว่าหน้าจอจะไม่แสดงรายการหนังและไม่เกิดข้อผิดพลาด ซึ่งลูกค้าเห็นด้วยเพราะระบบควรรองรับหน้าจอว่างได้อย่างชัดเจน

### 2. Step ใดที่เปลี่ยนถ้อยคำให้ตรงกับ step เดิมแทนการเขียน step ใหม่ เพราะอะไร
ในไฟล์ `movie_sort.feature` เราใช้ถ้อยคำ `Given a movie ... is in the catalog` และ `Then I should see no movies` ให้ตรงกับที่มีอยู่แล้วใน `movie_filter.feature` แทนการตั้งประโยคใหม่ เพราะ Cucumber สามารถจับคู่ไปใช้เมธอด Java เดิมใน `MovieSteps.java` ได้ทันที ช่วยลดโค้ดซ้ำซ้อนและดูแลรักษาง่ายขึ้น

### 3. ร่างผิดตรงไหนที่จะไม่เห็นถ้าไม่เขียน intent ก่อน และ customer proxy แก้อะไรที่ผู้ช่วยรู้เองไม่ได้
ถ้าไม่เขียน `intent` ก่อน เราอาจเผลอเก็บข้อกำหนดที่ AI คิดเกินมาจากคำสั่งลูกค้า เช่น การแจ้ง Error เมื่อพิมพ์ Rating ผิด หรือการจำค่าตัวกรองใน Local Storage และในส่วนที่ AI เดาเองไม่ได้อย่างการเลือกได้ทีละ 1 Rating หรือข้อความแจ้งเตือนเมื่อไม่พบหนัง ต้องให้ Customer Proxy เป็นผู้ตัดสินใจและยืนยันก่อนนำเข้า Backlog
